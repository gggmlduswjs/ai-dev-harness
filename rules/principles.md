# 원칙

모든 코드에 항상 적용한다. 프로젝트에 맞게 고치고, 맞지 않는 항목은 지운다.

## P1. 한 방향 의존
- 의존은 한 방향으로만 흐른다: {화면 → API → 서비스 → 저장소}. 반대 방향 import 금지.
- 다른 모듈의 데이터는 그 모듈의 공개 입구로만 다룬다.

## P2. 업무 규칙은 서비스 한 곳에
- 금액 · 상태 전이 · 권한 판단은 서비스 층에만 둔다. 화면 · API 핸들러에서 다시 계산하지 않는다.
- 규칙은 `docs/DOMAIN.md` 의 ID 와 짝지은 테스트가 지킨다.

## P3. 미측정 ≠ 0
- 값이 없거나 조회에 실패하면 「미측정」으로 다룬다. 0 으로 바꾸지 않는다. 분모가 0 이면 비율을 내지 않는다.

## P4. 경계에서 타입 계약 먼저
- 모듈 · API 경계의 입출력 타입을 먼저 정하고 구현한다.

## P5. 화면 값은 토큰에서만
- 색 · 간격 · 글자 · 반경 · 그림자는 디자인시스템 토큰만 쓴다(`docs/DESIGN_SYSTEM.md`).

## P6. 작게 바꾼다
- 이슈 범위의 파일만 고친다. 기능 PR 에 다른 리팩터링을 섞지 않는다.
- 원래 있던 죽은 코드는 지우지 말고 알린다. 내 변경이 만든 고아만 치운다.
