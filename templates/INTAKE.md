# 들여오기: {출처 — 예: 경쟁사 X 분석 · 현행 시스템 · 법령}

> 남의 것(경쟁사 · 옛 시스템 · 법 · 인터뷰)에서 알아낸 것을 **우리 규칙 · 화면 · 값**으로 바꾸는 한 번의 작업. 관찰은 우리 규칙이 아니다 — 사람이 판정한 줄만 `docs/` 로 들어간다.

## 순서

1. **모으기(AI)** — 원본에서 한 줄 = 하나의 관찰로 뽑아 `intake/<출처>.csv` 를 만든다. 원본 파일 · 위치를 `근거` 칸에 남긴다.
2. **나누고 추천하기(AI)** — 줄마다 `갈래` 와 `추천` 을 채운다. 같은 뜻의 줄은 묶는다(`묶음` 칸에 대표 줄 번호).
3. **판정(사람)** — 추천과 다르게 갈 줄만 `판정` 을 고친다. 비워 둔 줄은 추천을 받아들인 것으로 본다. 이 단계가 병목이니 2단계에서 추천을 성실히 채운다.
4. **옮기기(AI)** — `판정` 이 채택 · 수정인 줄을 갈래별 자리로 옮기고 `우리 ID` 를 채운다.
5. **끝** — CSV 는 근거로 남기고(지우지 않음) 다시 고치지 않는다. 다음 들여오기는 새 CSV.

## CSV 칸

| 칸 | 값 |
|---|---|
| `번호` | 1 부터 |
| `근거` | 원본 파일 · 줄 · 화면 · 캡처 |
| `원문` | 관찰한 그대로(짧게) |
| `갈래` | `값`(색 · 간격 등 토큰) · `패턴`(화면 틀 · 부품) · `규칙`(돈 · 상태 · 권한 · 정책) · `문구`(화면에 보일 말) · `버림후보` |
| `추천` | `채택` · `수정` · `버림` · `보류` |
| `이유` | 추천의 까닭 한 줄(우리 PRD 범위 · 이미 있음 · 법 · 저작권 …) |
| `판정` | 사람이 고칠 때만. 비우면 추천 그대로 |
| `우리 말` | 수정 · 채택한 내용을 **우리 말로**. 남의 문구 · 값을 그대로 옮기지 않는다 |
| `묶음` | 같은 뜻 줄의 대표 번호 |
| `우리 ID` | 옮긴 뒤 채움 — `docs/DOMAIN.md` 규칙 ID · `docs/SCREENS.md` 화면 ID · 패턴 이름 · 토큰 이름 |

## 갈래별 자리

| 갈래 | 옮길 곳 | 지키는 것 |
|---|---|---|
| 값 | 디자인시스템 토큰 파일 | 토큰 검사 |
| 패턴 | `docs/DESIGN_SYSTEM.md` 패턴 표 + `templates/PATTERN.md` | 패턴 코드 |
| 규칙 | `docs/DOMAIN.md` 표(ID) | 규칙 ID 마다 테스트 하나 |
| 문구 | 화면 이슈의 「이 화면만 다른 것」 표 | 화면 문구 대조 검사 |

## 하지 않는 것

- 판정 전에 `docs/` 를 고치지 않는다.
- 남의 화면 문구 · 값 · 코드를 그대로 쓰지 않는다. 구조 · 원칙만 가져오고 `우리 말` 로 다시 쓴다.
- 관찰 하나를 규칙 여러 개로 부풀리지 않는다. 묶어서 줄인다.
