# 로드맵

순서와 「끝나는 기준」만 적는다. 날짜 · 진행률 · 담당은 GitHub Issues 가 갖는다. 끝나는 기준은 **실행할 수 있는 명령**이나 **사람이 화면에서 확인할 수 있는 한 문장**이어야 한다.

데이터 모양(식별자 · 상태 · 버전)은 0단계부터 둔다. 나중에 붙이면 그때까지 쌓인 데이터를 다룰 길이 없다.

## 0단계: 뼈대

- 저장소 · CI · 배포 경로
- 디자인시스템 토큰 + 패턴 2~3개(가장 많이 쓰일 것)
- 인증 · 권한 뼈대
- **끝나는 기준.** {예: `npm run build && npm test` 통과, 빈 화면이 운영 주소에 뜬다}

## 1단계: {흐름 하나를 끝까지}

{가장 중요한 업무 흐름 하나를 처음부터 끝까지. 화면 여러 개를 얕게 만들지 않는다.}

- {화면 · 기능}
- **끝나는 기준.** {예: 실제 데이터 한 건이 수집 → 처리 → 완료까지 화면에서 보인다}
