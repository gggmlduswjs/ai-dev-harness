# 기존 프로젝트에 적용하기

> **원칙:** 폴더를 바로 옮기거나 기존 문서를 덮어쓰지 않습니다. **현재 정본 → 이 틀의 역할**을 먼저 대응시키고, 위험이 작은 단계부터 한 단계씩 PR 하나로 진행합니다.

조사·계획·구현은 [일상 가이드의 작업 절차](guides/2-daily-loop-and-second-brain.md#작업-절차)를 따릅니다. 프로젝트의 AI 역할·worktree 기준을 우선하며 Claude executor, Claude 기획 + Codex 구현, Codex 단독도 같은 승인·인계·검증 계약을 따릅니다. 아래는 **문서 체계의 적용 절차**이며 코드 구조를 전면 변경하는 승인이나 계획을 대신하지 않습니다. 기존 제품을 리팩토링할 때는 동작·테스트·DB·외부 API·배포 경로의 참조와 의존성을 먼저 조사하고, 도메인별로 범위·완료 조건·필요한 검증·되돌리는 방법을 계획합니다. 실제 프로젝트의 안전 규칙과 정본 경로를 우선하고, 구조·운영 변경은 승인된 범위에서 단계별 PR로 진행합니다.

## 단계

| 단계 | 할 일 | 위험 |
|---|---|---|
| 0. 조사 | 읽기 전용. 현재 요청/Issue가 연결한 문서와 관련 코드부터 실제 정본·참조를 확인합니다. 중요한 정보가 부족하거나 중복 정본이 의심될 때 필요한 범위만 넓혀 `type`/`status`·`owner-of` 중복 후보를 확인합니다. **아무것도 바꾸지 않습니다.** | 없음 |
| 1. 참조 스캔 | 어떤 코드·스크립트·CI·테스트가 `docs/` 경로를 읽는지 찾습니다. 옮길 수 있는 문서와 없는 문서를 나눕니다. | 없음 |
| 2. 라벨 | 작은 폴더 하나에 라벨 4줄만 붙입니다. **이동·삭제는 하지 않습니다.** | 매우 낮음 |
| 3. 결정 통합 | 흩어진 결정 기록을 한 곳으로 합칩니다. | 낮음 |
| 4. 이동 | 참조가 없는 문서부터 옮깁니다. 경로가 바뀌는 문서는 코드·CI 수정을 **같은 PR**에 넣습니다. `Historical`은 `_archive/`로. | 중간 |
| 5. 검사 | 라벨 누락·`owner-of` 중복을 CI로 잡습니다(`docs/CONVENTIONS.md` 5장). | 낮음 |

## 반드시 지킬 것

- 문서 전체 점검은 그 점검을 요청한 작업에서만 합니다. 일상 개발마다 전체 문서·과거 감사·개인 위키를 먼저 읽지 않습니다. 새 문서를 만들기 전에 관련 기존 정본과 경로를 찾아 수정·연결할 자리를 확인합니다.

- **CI·테스트·스크립트가 문서를 읽는 경우가 있습니다**(예: 결정 기록·아키텍처 문서를 검증하는 CI). 1단계 없이 옮기면 CI가 깨집니다.
- 이미 쌓인 과거 감사·조사 문서는 **대량 재작성하지 않습니다.** 새로 쓰는 문서부터 새 양식을 쓰고, 기존 문서는 손댈 때만 바꿉니다.
- 정본이 둘로 갈라져 있는 주제(예: 화면 계약이 두 곳)는 **어느 쪽이 정본인지 먼저 정하고** 합칩니다. 정하기 전에는 옮기지 않습니다.
- 문서 정리 때문에 **코드 폴더를 같이 건드리지 않습니다.** 앱 분리·설정 파일 이동은 별도 작업입니다.
- 시범은 **작은 폴더 하나**로 합니다. 결과가 맞는지 확인한 뒤 넓힙니다.

## 프로젝트 위키(선택·시험적)

기존 프로젝트에는 `_brain/`를 **위 단계가 끝난 뒤** 추가합니다. 슬랙·회의록 전체를 옮기지 말고 의사결정 스레드 5~10개로 시작하고, 이미 있는 정본(Spec·ADR·Linear)은 링크만 합니다. `raw/`는 반드시 `.gitignore`에 넣습니다. 스킬(wiki-ingest 등)은 wiki-template 구조를 기준으로 하므로 `_brain/` 안에서도 `raw/` 와 `wiki/` 2층을 유지합니다. 필요 없으면 생략합니다(자세한 기준: [2-daily-loop-and-second-brain.md](guides/2-daily-loop-and-second-brain.md) 4장).

## 문서 폴더만 먼저 적용할 때의 매핑 예

| 기존에 흔한 것 | 이 틀의 자리 |
|---|---|
| 세팅·개발 절차 문서 | `docs/guides/` (순서가 있으면 번호) |
| 용어집·표·규격 | `docs/reference/` |
| 기능별 명세(화면 계약 포함) | `docs/features/` |
| 결정표·ADR·DECISIONS | `docs/ADR.md` + `docs/adr/` **한 곳** |
| 구현 계획서 | `.dev/plans/` |
| 조사 문서 | `.dev/research/` |
| 지난 기록 | `docs/_archive/` |
