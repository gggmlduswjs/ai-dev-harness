# 설계 문서

이 폴더가 제품의 **현재 정본**이다. 문서와 코드가 다르면 문서가 맞다 — 문서를 먼저 고치고 코드를 맞춘다.

## 읽는 순서

| 문서 | 무엇 | 언제 고치나 |
|---|---|---|
| [PRD.md](PRD.md) | 누구의 어떤 문제를 · 어디까지 만들고 무엇을 안 만드나 | 범위가 바뀔 때 |
| [DECISIONS.md](DECISIONS.md) | 정한 것과 그 까닭 · 아직 안 정한 것 | 결정할 때마다 덧붙임 |
| [DOMAIN.md](DOMAIN.md) | 데이터 단위 · 상태전이 · 금액 · 권한 — 업무 규칙 | 규칙이 바뀔 때(테스트와 같이) |
| [SCREENS.md](SCREENS.md) | 화면 목록 · 쓰는 패턴 · 다루는 데이터 단위 | 화면이 생기거나 없어질 때 |
| [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) | 토큰 · 패턴 · 공통 상태 · 금지 목록 | 패턴이 생길 때 |
| [ARCHITECTURE.md](ARCHITECTURE.md) | 모듈 경계 · 데이터 흐름 · 외부 연동 | 구조가 바뀔 때 |
| [ROADMAP.md](ROADMAP.md) | 단계와 단계마다 끝나는 기준 | 단계를 마치거나 순서를 바꿀 때 |

## 문서 규칙

1. **한 사실은 한 곳에.** 같은 내용이 두 곳에 있으면 하나를 지우고 링크한다.
2. **코드가 진실인 것은 코드에.** 설정값 · 상수 · 계산 · 부품 모양은 문서에 복사하지 않고 위치를 가리킨다. 문서에는 결정의 배경처럼 코드에 담을 수 없는 것만 둔다.
3. **표로 쓴다.** 규칙 · 상태 · 화면 목록은 산문 대신 표로 쓴다. 표 한 줄이 테스트 · 검사 한 개로 옮겨질 수 있어야 한다.
4. **용어를 고정한다.** 같은 것을 다른 이름으로 부르지 않는다. 새 용어는 [DOMAIN.md](DOMAIN.md) 「용어」 표에 먼저 넣는다.
5. **진행 상태를 적지 않는다.** 진행률 · 담당 · 마감은 GitHub Issues 가 갖는다.
6. **모르는 것은 `?` 로 적는다.** 빈칸으로 두거나 추측으로 채우지 않는다.

## 이 폴더에 두지 않는 것

- 작업 하나의 계획 · 조사 메모 → 그 GitHub Issue 댓글이나 PR
- 화면마다 칸 · 버튼을 산문으로 늘어놓은 명세 → 패턴 코드와 이슈의 「끝나는 기준」
