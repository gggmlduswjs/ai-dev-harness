# UI 공통 설계 가이드

> **목적:** 프로젝트 전체에서 반복 적용할 화면·디자인 규칙을 정의합니다. 특정 기능의 업무 흐름은 해당 Feature 문서에 기록합니다.

## UI 스택과 부품 선택 규칙 (Vue + Element Plus 프로젝트일 때)

> 다른 스택이면 **이 절을 그 스택의 부품·토큰 규칙으로 바꿉니다.** 이 문서의 나머지 절(원칙, 레이아웃, 접근성 등)은 스택과 무관합니다.

| 층 | 도구 | 역할 |
|---|---|---|
| 부품 | Element Plus | 표·폼·모달 등 공식 컴포넌트 |
| 디자인 규칙 | `refactoring-ui` 스킬 | 간격·글자·색·그림자·모서리를 정해진 단계에서만 선택 |
| 토큰 | 토큰 파일 1개 | 값의 정본. Element Plus의 CSS 변수(`--el-*`)를 덮어씀 |

1. **부품은 Element Plus 공식 컴포넌트에서 먼저 고릅니다.** 직접 만드는 것은 공식에 없을 때만입니다.
2. **임의 값을 쓰지 않습니다.** 간격·글자 크기·색·그림자·모서리는 토큰(정해진 단계)에서만 고릅니다.
3. **Element Plus 스타일은 컴포넌트마다 덮지 않습니다.** 토큰 파일에서 `--el-*` 변수로 **한 번만** 맞춥니다.
4. **화면별 부품 표를 문서에 두지 않습니다.** 부품·props는 코드가 정본이고, 기능 문서에는 화면이 하는 일만 적습니다.
5. **"어색하다"는 `refactoring-ui` 스킬로 진단**해서 구체적인 수정(위계, 대비, 간격 단계)으로 바꿉니다.
